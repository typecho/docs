# 永久链接

后台“设置 → 永久链接”（`admin/options-permalink.php`），只有管理员能打开。这里决定是否使用地址重写（伪静态），以及文章、独立页面和分类的地址格式。Web 服务器端需要的重写规则见[Web 服务器配置](../operations/web-server.md)。

## 是否使用地址重写功能 {#rewrite}

| 界面选项 | `rewrite` 值 | 生成的地址 |
|---|---|---|
| 不启用（默认） | `0` | `https://example.com/index.php/archives/1/` |
| 启用 | `1` | `https://example.com/archives/1/` |

启用前，Web 服务器必须已经配置好重写规则，把不存在的路径交给 `index.php` 处理。

### 开启时的自动检测：`checkRewrite()` {#check}

选择“启用”并保存时，Typecho 会先做一次检测，通过才保存：

1. 如果 PHP 以 Apache 模块（`mod_php`）运行、根目录没有 `.htaccess` 且可写，先自动写入一份 `.htaccess`。**PHP-FPM 等其他运行方式下不会自动写入**，需要自己创建，内容见[Web 服务器配置](../operations/web-server.md#htaccess)。
2. 从服务器**自己**向 `站点地址/action/ajax` 发一个请求（不带 `index.php`），返回 `OK` 就算通过。
3. 如果第 1 步写入了文件而检测没通过，换用另一种兼容写法再写一次、再检测；仍然失败就删掉自己写入的文件。

两种结果：

- **检测失败**（例如服务器上没有任何重写规则）：页面提示“重写功能检测失败, 请检查你的服务器设置”，下面多出一个“如果你仍然想启用此功能, 请勾选这里”的复选框，`rewrite` 仍为 0；
- **检测通过**（重写规则已生效）：保存成功，前台链接变为不带 `index.php` 的形式。

在 Apache `mod_php` 下，根目录不可写时，失败提示还会加上“我们检测到你使用了apache服务器, 但是程序无法在根目录创建.htaccess文件……请调整你的目录权限, 或者手动创建一个.htaccess文件.”。

检测失败的常见原因还有：服务器无法通过站点地址访问到自己（内网、防火墙、Docker 中的端口映射、站点地址的域名在服务器上解析不到）。这种情况下即使规则正确也会失败。

### 检测失败但确定规则没问题

两种办法：

- 勾选“如果你仍然想启用此功能, 请勾选这里”（`enableRewriteAnyway`）后再保存，跳过检测；
- 在 `config.inc.php` 中定义 `__TYPECHO_REWRITE__`，见[配置文件：永久链接](../operations/config-file.md#rewrite)。定义后这个选项和检测都不再出现在后台。

:::caution 跳过检测前请确认规则确实生效
在没有任何重写规则时勾选“仍然启用”，保存会成功，但前台所有文章链接（如 `/archives/1/`）都变成 404。后台不受影响（`/admin/` 是真实目录），回到这里改回“不启用”即可恢复。
:::

### 关闭地址重写会删除 `.htaccess` {#htaccess-delete}

在**地址重写为“不启用”的状态下保存这个页面**（不论改的是哪一项），Typecho 会删除网站根目录的 `.htaccess`，手动创建的也不例外：只要 `rewrite` 为 0，保存一次永久链接设置，`.htaccess` 就会被删除。从“启用”切换到“不启用”的那一次保存不会删除，之后再保存才会。

如果你的 `.htaccess` 里还写了其他规则（防盗链、HTTPS 跳转等），请先备份，或者在开启地址重写之前不要在这个页面反复保存。

## 自定义文章路径 {#post-pattern}

“自定义文章路径”（`postPattern`）有四种预设和一种个性化定义：

| 界面名称 | 规则 | 示例 |
|---|---|---|
| 默认风格 | `/archives/{cid}/` | `/archives/1/` |
| wordpress风格 | `/archives/{slug}.html` | `/archives/hello-world.html` |
| 按日期归档 | `/{year}/{month}/{day}/{slug}.html` | `/2026/10/16/hello-world.html` |
| 按分类归档 | `/{category}/{slug}.html` | `/default/hello-world.html` |
| 个性化定义 | 在文本框（`customPattern`）中填写 | 例如 `/{year}/{cid}.html` |

可用参数（界面说明原文：“`{cid}` 日志 ID, `{slug}` 日志缩略名, `{category}` 分类, `{directory}` 多级分类, `{year}` 年, `{month}` 月, `{day}` 日”）：

| 参数 | 含义 |
|---|---|
| `{cid}` | 文章 ID（数字） |
| `{slug}` | 文章的网址缩略名 |
| `{category}` | 文章第一个分类的缩略名 |
| `{directory}` | 包含所有父级分类的多级路径，例如 `tech/php` |
| `{year}` / `{month}` / `{day}` | 发布日期，4 位年、2 位月、2 位日 |

例如个性化定义 `/{year}/{cid}.html` 保存后，文章地址形如 `/2026/1.html`。

注意：

- 规则中至少要有 `{cid}` 或 `{slug}` 之一来区分文章，否则多篇文章会得到相同的地址。个性化定义的输入框**不会**检查这一点。
- 保存个性化定义时，Typecho 会检查它是否会和分类、标签等已有规则冲突。冲突时**仍然保存**，只提示“自定义链接与现有规则存在冲突! 它可能影响解析效率, 建议你重新分配一个规则.”。例如保存 `/tag/{slug}/` 后，`/tag/某某/` 形式的地址全部被当成文章解析，标签页无法再访问。看到这个提示请换一个规则。
- **修改规则后旧地址不会跳转**。例如从默认风格改为 `/{year}/{cid}.html` 后，原来的 `/archives/1/` 返回 404。已经被搜索引擎收录或被外站引用的站点，修改前要想好，或者在 Web 服务器上自己配置旧地址的跳转。界面上也提醒了“一旦你选择了某种链接风格请不要轻易修改它.”

## 独立页面路径与分类路径 {#page-category}

| 界面名称 | 字段 | 默认值 | 可用参数 |
|---|---|---|---|
| 独立页面路径 | `pagePattern` | `/{slug}.html` | `{cid}` 页面 ID、`{slug}` 页面缩略名、`{directory}` 多级页面 |
| 分类路径 | `categoryPattern` | `/category/{slug}/` | `{mid}` 分类 ID、`{slug}` 分类缩略名、`{directory}` 多级分类 |

- 两者都必须至少包含一个参数。例如把独立页面路径改为 `/about.html` 时，提示“独立页面路径中没有包含 `{cid}` 或者 `{slug}`”，整页设置都没有保存（`{directory}` 也算合法参数，提示中没写出来）。
- `{directory}` 用于页面树和分类树，生成包含父级缩略名的多级路径；独立页面路径改为 `/{directory}.html` 时，顶级页面的地址不变（如 `/start-page.html`）。
- 分类的分页地址自动生成为“分类路径 + `/页码/`”。
- 标签、作者、搜索、日期归档等其他地址的规则不能在后台修改。

这三项（文章、页面、分类路径）保存在 `routingTable` 选项中，与“阅读设置”中的文章列表页路径在同一张路由表里。
