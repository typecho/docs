# 阅读设置

本页对应后台“设置 → 阅读”（`admin/options-reading.php`），只有管理员可以访问。这里决定前台首页显示什么、每页多少篇文章、日期怎么显示，以及订阅源输出全文还是摘要。

## 字段一览

| 界面名称 | 选项名 | 默认值 | 说明 |
|---|---|---|---|
| 文章日期格式 | `postDateFormat` | `Y-m-d` | 见[下文](#date-format) |
| 站点首页 | `frontPage` | `recent` | 见[下文](#front-page) |
| 同时将文章列表页路径更改为 | `frontArchive`、`archivePattern` | 不勾选，`/blog/` | 只在首页不是“显示最新发布的文章”时出现 |
| 文章列表数目 | `postsListSize` | 10 | 侧边栏“最新文章”这类列表显示的篇数 |
| 每页文章数目 | `pageSize` | 5 | 首页、分类、标签、搜索、归档等文章列表每页显示的篇数 |
| 聚合全文输出 | `feedFullText` | 全文输出（`1`） | `0` 仅输出摘要，`1` 全文输出，见[订阅源与离线客户端](../content/feeds-xmlrpc.md#feeds) |

## 文章日期格式 {#date-format}

“文章日期格式”（`postDateFormat`）是主题输出文章日期时的默认格式。写法是 PHP 的 `date()` 格式字符，后台说明中的“PHP 日期格式写法”链接指向 PHP 手册的这个函数。说明中也提醒了：“在某些主题中这个格式可能不会生效, 因为主题作者可以自定义日期格式.”

常用写法，以 2026 年 10 月 16 日下午 5 点 23 分为例：

| 格式 | 输出 |
|---|---|
| `Y-m-d`（默认） | 2026-10-16 |
| `Y年n月j日` | 2026年10月16日 |
| `Y年m月d日 H:i` | 2026年10月16日 17:23 |
| `M j, Y` | Oct 16, 2026 |
| `D, d M Y` | Fri, 16 Oct 2026 |

`Y` 四位年份，`m` / `n` 月份（带 / 不带前导零），`d` / `j` 日，`H` 24 小时制的小时，`i` 分钟；字母要原样输出时前面加反斜杠。完整的说明和更多例子见[评论设置：评论日期格式](./discussion.md#date-format)。例如改为 `Y年n月j日` 后，默认主题文章列表中的日期显示为“2026年10月16日”。

格式中不能包含 `<`、`>` 等特殊字符，否则提示“请不要在日期格式中使用特殊字符”。

## 站点首页 {#front-page}

“站点首页”（`frontPage`）有三种取值，后两种只在条件满足时出现在界面上：

| 界面选项 | 保存的值 | 出现条件 | 首页显示 |
|---|---|---|---|
| 显示最新发布的文章 | `recent` | 总是 | 默认，按时间倒序列出文章 |
| 使用 [页面] 页面作为首页 | `page:页面ID`，例如 `page:2` | 至少有一个已发布的独立页面 | 所选独立页面的内容 |
| 直接调用 [文件] 模板文件 | `file:文件名`，例如 `file:home.php` | 当前主题中有声明为首页模板的文件 | 所选模板文件的输出 |

### 使用独立页面作为首页

例如选择“关于”页面后，`frontPage` 保存为 `page:2`，首页显示这个页面的内容；页面原来的地址（如 `/start-page.html`）仍然可以访问。在首页上对这个页面发表评论时，“检查评论来源页”会把首页地址视为合法来源。

### 直接调用模板文件

主题目录中的 PHP 文件只要在开头注释里写有 `@package index`，就会出现在“直接调用 [文件] 模板文件”的下拉框中（`index.php` 本身除外）。两个自带主题都没有这样的文件，所以默认看不到这一项。例如在主题中新建 `home.php`：

```php
<?php
/**
 * 自定义首页
 *
 * @package index
 */
if (!defined('__TYPECHO_ROOT_DIR__')) exit;
?>
<!-- 首页内容 -->
```

选中后 `frontPage` 保存为 `file:home.php`，首页直接输出这个文件。更换主题时，如果首页设置为模板文件，会自动恢复为“显示最新发布的文章”。

:::caution 模板文件首页下 `/page/2/` 会报错
1.3.0 中首页设为模板文件后，访问首页的分页地址（如 `/page/2/`）返回 500 错误（`Typed property Widget\Archive::$currentPage must not be accessed before initialization`）。模板文件中不要输出指向 `/page/N/` 的分页链接。
:::

:::caution 模板文件中调用 header() 会报错
在 1.3.0 中，首页设为模板文件时，Typecho 不会初始化订阅地址。只要模板（或它引入的 `header.php`）调用了 `$this->header()`，首页就会报错：`Typed property Widget\Archive::$archiveFeedUrl must not be accessed before initialization`。这个问题在 1.3.0 之后的代码中才修复。在模板开头先用 `setArchiveFeedUrl()` 等方法设置好订阅地址即可避免，写法见主题开发中的[首页模板](../../develop/theme/custom-templates.md#首页模板package-index)。
:::

### 文章列表页 {#front-archive}

首页改为页面或模板文件后，原来首页上的文章列表就没有地方显示了。勾选“同时将文章列表页路径更改为 [路径]”（`frontArchive`，路径保存在路由表的 `archive` 规则中，默认 `/blog/`）后，文章列表会出现在这个路径下，分页地址为 `路径/page/N/`。

例如把路径改为 `/posts/` 并保存后，`/posts/` 显示文章列表，原来的 `/blog/` 返回 404。不勾选时这个路径也返回 404，访客只能通过分类、标签、归档等页面看到文章列表。首页改回“显示最新发布的文章”时，`frontArchive` 自动变为 0。

## 文章列表数目与每页文章数目

- “每页文章数目”（`pageSize`）影响所有文章列表页的分页；改小后，分页数变多，原来的 `/page/N/` 地址对应的内容会变化。
- “文章列表数目”（`postsListSize`）只影响主题侧边栏等处的最新文章列表。

这两个数字都必须是整数，否则提示“请填入一个数字”。
