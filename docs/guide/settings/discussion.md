# 评论设置

后台“设置 → 评论”（`admin/options-discussion.php`），只有管理员能打开。这里的设置对全站所有文章和页面生效；单篇内容的“允许评论”“允许被引用”在编辑器中设置，评论的审核在“管理 → 评论”中进行，见[评论管理与审核](../content/comments.md)。

:::info 测试情况
本页每个字段的界面名称和选项名，都是在 Typecho 1.3.0 + Apache + PHP-FPM（PHP 8.5）+ SQLite 的后台中读取的，并与 `var/Widget/Options/Discussion.php` 的 `from()` 列表、表单定义以及实际读取这些选项的代码（`var/Widget/Feedback.php`、`var/Widget/Base/Comments.php`、`var/Widget/Comments/Archive.php`）逐项对照。实测了：修改评论日期格式后前台评论时间的变化、回复层数超出范围时的保存值、自动关闭天数和发言间隔的保存值。分页、排序、反垃圾、来源检查等其余选项的效果只核对了源码。
:::

## 评论日期格式 {#date-format}

“评论日期格式”（`commentDateFormat`）是主题输出评论日期时的默认格式（主题调用 `$comments->date()` 且没有自己指定格式时使用）。写法是 PHP 的 `date()` 格式字符，后台说明中的“PHP 日期格式写法”链接就指向 PHP 手册的这个函数。

默认值是 `F jS, Y \a\t h:i a`。常用写法，以 2026 年 10 月 16 日下午 5 点 23 分为例：

| 格式 | 输出 |
|---|---|
| `Y-m-d` | 2026-10-16 |
| `Y-m-d H:i` | 2026-10-16 17:23 |
| `Y年n月j日` | 2026年10月16日 |
| `Y年m月d日 H:i` | 2026年10月16日 17:23 |
| `n/j/Y` | 10/16/2026 |
| `M j, Y` | Oct 16, 2026 |
| `F jS, Y \a\t h:i a`（默认） | October 16th, 2026 at 05:23 pm |

常用格式字符：`Y` 四位年份，`m` / `n` 月份（带 / 不带前导零），`d` / `j` 日，`H` 24 小时制的小时，`h` 12 小时制的小时，`i` 分钟，`s` 秒，`a` am/pm。格式中的字母都会被当作格式字符，要原样输出字母时在前面加反斜杠，例如默认格式中的 `\a\t` 输出“at”。月份、星期的英文名称（`F`、`M`、`D`、`l`）不会随界面语言翻译。

实测把格式改为 `Y-m-d H:i` 后，默认主题的评论时间显示为 `2026-10-16 17:23`。文章的日期格式在[阅读设置](./reading.md#date-format)中单独设置。

## 评论列表数目

“评论列表数目”（`commentsListSize`，默认 10）是主题侧边栏“最近回复”这类评论列表显示的条数，与文章下方的评论列表无关。

## 评论显示（`commentsShow[]`） {#show}

这一组复选框决定评论在前台怎么显示。界面上提交的是 `commentsShow[]` 数组，保存时拆成下面这些独立的选项：

| 界面名称 | 选项名 | 默认 | 作用 |
|---|---|---|---|
| 仅显示评论, 不显示 Pingback 和 Trackback | `commentsShowCommentOnly` | 关 | 文章的评论列表和“最近回复”中只显示普通评论，引用通告和 Pingback 不显示（数据仍保存，后台照常管理） |
| 在评论中使用 Markdown 语法 | `commentsMarkdown` | 关 | 评论内容按 Markdown 解析；关闭时只自动分段 |
| 评论者名称显示时自动加上其个人主页链接 | `commentsShowUrl` | 开 | 评论者填写了网址时，名字链接到该网址 |
| 对评论者个人主页链接使用 nofollow 属性 | `commentsUrlNofollow` | 开 | 上述链接带 `rel="nofollow"` |
| 启用 Gravatar 头像服务, 最高显示评级为 [下拉框] 的头像 | `commentsAvatar`，下拉框为 `commentsAvatarRating` | 开，`G` | 评论者头像按邮箱从 Gravatar 获取；评级可选 `G`（普通）、`PG`（13岁以上）、`R`（17岁以上成人）、`X`（限制级），超过所选评级的头像不显示 |
| 启用分页, 并且每页显示 [数字] 篇评论, 在列出时将 [第一页 / 最后一页] 作为默认显示 | `commentsPageBreak`，数字为 `commentsPageSize`，下拉框为 `commentsPageDisplay` | 关，20，最后一页 | 评论分页。`commentsPageDisplay` 为 `last` 时，打开文章默认显示最后一页（最新的评论），为 `first` 时显示第一页 |
| 启用评论回复, 以 [数字] 层作为每个评论最多的回复层数 | `commentsThreaded`，数字为 `commentsMaxNestingLevels` | 开，5 | 嵌套回复，见下文 |
| 将 [较新的 / 较旧的] 的评论显示在前面 | `commentsOrder` | 较旧的（`ASC`） | `DESC` 新评论在前，`ASC` 旧评论在前 |

几点细节：

- **回复层数只能在 2 到 7 之间**。填写的数字超出范围时保存为最接近的边界值，实测填 10 保存为 7。回复超过最大层数时，不再继续缩进，而是挂到上一层评论下显示。
- 关闭“启用评论回复”后，所有评论按顺序平铺显示，主题的“回复”按钮通常也会消失。
- 这些选项能否生效，还取决于主题是否使用了 Typecho 的评论输出方法；自己实现评论列表的主题可能忽略其中一部分。

## 评论提交（`commentsPost[]`） {#post}

这一组决定访客提交评论时要满足什么条件。同样以 `commentsPost[]` 数组提交、拆成独立选项保存：

| 界面名称 | 选项名 | 默认 | 作用 |
|---|---|---|---|
| 所有评论必须经过审核 | `commentsRequireModeration` | 关 | 新评论进入“待审核” |
| 评论者之前须有评论通过了审核 | `commentsWhitelist` | 关 | 同一称呼和邮箱以前有过已通过的评论才直接通过，否则待审核；只在上一项关闭时起作用 |
| 必须填写邮箱 | `commentsRequireMail` | 开 | 未登录的评论者必须填邮箱，否则提示“必须填写电子邮箱地址” |
| 必须填写网址 | `commentsRequireUrl` | 关 | 未登录的评论者必须填个人主页，否则提示“必须填写个人主页” |
| 检查评论来源页 URL 是否与文章链接一致 | `commentsCheckReferer` | 开 | 见[下文](#referer) |
| 开启反垃圾保护 | `commentsAntiSpam` | 开 | 见[下文](#anti-spam) |
| 在文章发布 [数字] 天以后自动关闭评论 | `commentsAutoClose`，数字为 `commentsPostTimeout` | 关，30 | 文章发布超过 N 天后，评论和引用都自动关闭。界面填写天数，数据库中保存为秒数，实测填 14 保存为 `1209600` |
| 同一 IP 发布评论的时间间隔限制为 [数字] 分钟 | `commentsPostIntervalEnable`，数字为 `commentsPostInterval` | 开，1 | 同一 IP 在同一篇文章下两次评论的最短间隔；太快时提示“对不起, 您的发言过于频繁, 请稍候再次发布.”。文章作者和编辑、管理员不受限制。界面填写分钟数，保存为秒数，实测填 2 保存为 `120` |

:::note 发言间隔只能填整数
源码会把分钟数保留一位小数（例如 0.5 分钟 = 30 秒），但输入框是普通的数字框，实测填 `0.5` 时浏览器提示“请输入有效值”，表单无法提交。所以在后台只能填整数分钟。
:::

审核相关的状态和处理方式见[评论管理与审核](../content/comments.md)。

### 来源页检查 {#referer}

开启后，Typecho 要求评论请求带有 `Referer`，而且它的域名与文章地址相同、路径以文章地址开头（以某个独立页面作为首页时，首页地址也算），否则拒绝并提示“评论来源页错误.”（HTTP 403）。

这能挡住直接向评论接口提交的机器人，但也会误伤关闭了 `Referer` 的访客：浏览器隐私插件、`Referrer-Policy: no-referrer` 响应头、跨域名的评论框都会导致评论失败。遇到“评论来源页错误”时先检查这些。

### 反垃圾保护 {#anti-spam}

开启后，主题页面头部（主题模板调用 `$this->header()` 的位置）会输出一段脚本：访客在页面上滚动、移动鼠标、按键或触摸后，脚本才把一个校验值加入评论表单。没有这个校验值的提交会被拒绝，页面直接跳回文章。

所以下面这些情况下评论会提交失败：访客浏览器禁用了 JavaScript；主题没有调用 `$this->header()`。排查评论提交不上时，可以先临时关闭这一项确认是否是它的原因。

## 允许使用的HTML标签和属性 {#html-tags}

“允许使用的HTML标签和属性”（`commentsHTMLTagAllowed`）默认为空，即评论中只保留段落和换行（`<p>`、`<br>`），其他 HTML 标签都会被去掉。需要放行时按界面中的示例填写：

```html
<a href=""> <img src=""> <blockquote>
```

标签后面列出的属性才会保留。开启“在评论中使用 Markdown 语法”后，Markdown 生成的 HTML 也要经过这里的过滤，例如想让 Markdown 链接生效，需要放行 `<a href="">`。
