# 附件与文件管理

附件（attachment）就是上传到站点的图片和其他文件，后台菜单中叫“文件”。上传入口在文章和页面编辑器右侧的“附件”栏，集中管理在“管理 → 文件”（`manage-medias.php`）。

## 谁能上传

| 操作 | 最低角色 |
|---|---|
| 在编辑器中上传、编辑和删除**自己**的文件（`media.php?cid=`） | 贡献者 |
| 进入“管理 → 文件”管理所有人的文件 | 编辑 |
| 修改允许上传的文件类型 | 管理员 |

## 上传

在编辑器右侧切换到“附件”栏，把文件拖到“拖放文件到这里”区域，或点击“选择文件上传”。

- 1.3.0 每次选择一个文件（一次选择多个文件是 1.3.0 之后合并的改动，尚未发布）。
- 单个文件的大小上限取自 PHP 的 `upload_max_filesize`；超出时显示“文件大小超过限制”。同时还受 PHP `post_max_size` 和 Web 服务器（如 nginx 的 `client_max_body_size`）限制。
- 扩展名不在允许列表中时显示“某某 上传失败 / 文件扩展名不被支持”，两秒后自动消失。
- 上传成功后，点击文件名把它插入正文，见[撰写文章](./posts.md#attachments)。

### 文件保存在哪里

默认保存在网站目录的 `usr/uploads/年/月/` 下，文件名是一串随机数字加原扩展名（扩展名转为小写），例如：

```text
usr/uploads/2026/10/3396430629.png
```

原来的文件名只保存在数据库中，作为附件的标题显示。访问地址是“站点地址 + 这个路径”。目录不存在时会自动逐级创建，所以 `usr/uploads` 必须让 PHP 可写。要改变存放位置或让附件走 CDN，见[附件存储位置](../operations/uploads-storage.md)。

## 允许上传的文件类型 {#types}

在“设置 → 基本”的“允许上传的文件类型”中设置，对应选项 `attachmentTypes`，**默认只允许图片**。

| 界面上的选项 | 保存的值 | 实际允许的扩展名 |
|---|---|---|
| 图片文件 | `@image@` | gif jpg jpeg png tiff bmp webp |
| 多媒体文件 | `@media@` | mp3 mp4 mov wmv wma rmvb rm avi flv ogg oga ogv |
| 常用档案文件 | `@doc@` | txt doc docx xls xlsx ppt pptx zip rar pdf |
| 其他格式 | 文本框中填写的扩展名 | 用半角逗号隔开，例如 `cpp, h, mak` |

保存后，选项的值是这些项目用逗号连起来的字符串。例如勾选“图片文件”“常用档案文件”和“其他格式”，在文本框中填 `svg, PHP, md`，保存的是：

```text
@image@,@doc@,svg,md
```

- 自定义扩展名会转为小写；`php`、`php4`、`php5`、`sh`、`asp`、`jsp`、`rb`、`py`、`pl`、`dll`、`exe`、`bat` 会被直接去掉，无法通过这里放行。
- 允许 `svg` 时要注意：SVG 文件可以包含脚本，访问者直接打开时脚本会在你的域名下运行。只在信任所有能上传文件的用户时才开放。

:::caution avif 实际不能上传
“图片文件”后面的说明写着 `(gif jpg jpeg png tiff bmp webp avif)`，但 1.3.0 实际展开 `@image@` 时没有 `avif`（`var/Widget/Options.php` 的 `___allowedAttachmentTypes()`），上传 `.avif` 文件会提示“文件扩展名不被支持”。需要上传 avif 时，勾选“其他格式”并填写 `avif`。
:::

## 编辑与替换文件 {#replace}

在编辑器“附件”栏点击文件旁的编辑图标，或在“管理 → 文件”中点击文件名，进入“编辑 文件名”页面（`media.php?cid=`）：

| 界面名称 | 字段 | 说明 |
|---|---|---|
| 标题 * | `name` | 默认是上传时的原文件名 |
| 缩略名 | `slug` | 附件页面地址中使用 |
| 描述 | `description` | 有的主题会显示 |

页面上方的上传区域用来**替换文件**：上传一个新文件，原文件被覆盖，提示“文件 某某 已经替换”。

- 替换后**路径和访问地址都不变**，正文中已经插入的地址仍然有效；标题也不变。
- 新文件的扩展名必须和原文件相同。扩展名不同时（例如用 `.md` 替换 `.txt` 文件）只显示“上传失败”，不说明原因。
- 浏览器或 CDN 可能缓存旧文件，替换后看不到变化时请强制刷新或清除 CDN 缓存。

## 删除文件

- 在编辑器“附件”栏点击删除图标（确认“确认要删除文件 某某 吗?”），或在“管理 → 文件”中勾选后选择“删除”（确认“你确认要删除这些文件吗?”）。
- 删除会同时删掉数据库记录和磁盘上的文件。正文中引用它的地址会失效，需要自己修改正文。
- 如果在 `config.inc.php` 中定义了 `__TYPECHO_UPLOAD_ROOT_DIR__`，1.3.0 删除附件时不会删除磁盘上的文件，见[附件存储位置](../operations/uploads-storage.md)。

## 未归档文件 {#unattached}

“管理 → 文件”中的“所属文章”列显示文件属于哪篇文章或页面。没有所属内容的文件叫**未归档文件**，常见来源：

- 删除了文章或页面——它们的附件不会被删除，而是变成未归档；
- 在新文章中上传了文件，却没有保存或发布这篇文章。

列表上方的“清理未归档文件”按钮（确认“您确认要清理未归档的文件吗?”）会删除所有未归档文件，包括磁盘上的文件。如果正文中直接引用了这些文件的地址（例如删除旧文章前复制过图片地址），清理后这些地址会失效，执行前请先确认。

## 附件页面

每个附件也有自己的前台页面（默认地址 `/attachment/{cid}/`），主题可以用它展示图片或下载链接，访客可以在附件页面评论（附件默认允许评论）。
