# 分类与标签

分类和标签只用于文章，独立页面没有。两者都在“管理”菜单下，**编辑及以上角色**才能管理；贡献者写文章时可以勾选已有分类、输入标签（新标签会自动创建），但不能进入管理页面。

| | 分类 | 标签 |
|---|---|---|
| 层级 | 可以多级（分类树） | 没有层级 |
| 创建 | 只能在“管理 → 分类”中创建 | 写文章时输入即创建，也可以在“管理 → 标签”中创建 |
| 每篇文章 | 至少一个（不选则归入默认分类） | 可以没有 |
| 前台地址 | `/category/{slug}/` | `/tag/{slug}/` |

## 管理分类

“管理 → 分类”（`manage-categories.php`）列出所有顶级分类，表格包含以下几列：名称、子分类、缩略名、默认、文章数。

### 新增与编辑

点击标题旁的“新增”进入 `category.php`：

| 界面名称 | 字段 | 说明 |
|---|---|---|
| 分类名称 * | `name` | 必填，不能与同一父级分类下的已有分类重名 |
| 分类缩略名 | `slug` | 用于地址，建议使用字母、数字、下划线和横杠；留空时由名称生成，不能与已有分类重复（不同父级下的同名分类也要使用不同的缩略名） |
| 父级分类 | `parent` | “不选择”为顶级分类；选择后“此分类将归档在您选择的父级分类下” |
| 分类描述 | `description` | 有的主题会显示 |

点击分类名称进入编辑；点击名称旁的外链图标打开它的前台页面。

### 分类树 {#tree}

- “子分类”列中的“新增”为这个分类新建子分类（`category.php?parent=分类ID`，父级分类已预先选好）；有子分类时显示数量，点击进入子分类列表（`manage-categories.php?parent=分类ID`），标题为“管理 技术 的子分类”。
- 写文章时，子分类在分类列表中缩进显示。
- 分类地址的规则在“设置 → 永久链接”的“分类路径”中修改，可用参数为 `{mid}`、`{slug}` 和表示多级分类的 `{directory}`。

### 排序

在分类列表中**拖动行**改变顺序，松开后立即保存（同一层级内）。主题输出分类列表时按这个顺序排列。

### 默认分类 {#default}

安装后自带一个名为“默认分类”（缩略名 `default`）的分类。默认分类的作用：

- 写新文章时，它预先被勾选；
- 文章保存时如果没有选择任何分类，会归入默认分类。

默认分类在列表的“默认”列中有标记。要更换，点击另一个分类那一行的“默认”（鼠标悬停提示“设为默认”），提示“某某 已经被设为默认分类”。

:::caution 不要删除默认分类
1.3.0 允许删除当前的默认分类，删除后设置中仍指向那个已经不存在的分类，结果是：写新文章时没有任何分类被预先勾选，不选分类直接发布的文章**没有任何分类**。如果已经删了，在分类列表中把另一个分类设为默认即可恢复。
:::

### 删除与合并

勾选分类后，在“选中项”菜单中操作：

| 操作 | 结果 |
|---|---|
| 删除 | 删除分类本身和它与文章的关联。子分类上移一级 |
| 刷新 | 重新计算文章数，见[下文](#counts) |
| 合并到（右侧选择目标分类） | 所选分类下的文章并入目标分类，所选分类被删除，它们的子分类改挂到目标分类下 |

删除时会弹出“此分类下的所有内容将被删除, 你确认要删除这些分类吗?”。**这句话不准确**：删除分类后文章还在，只是不再属于这个分类；如果某篇文章只属于这一个分类，它就变成没有分类的文章，并不会自动归入默认分类，需要手动重新指定。

“合并到”的下拉框只列出当前列表这一层的分类。要把子分类合并进其他层级的分类，可以先在编辑页把它的父级分类改到同一层。

## 管理标签

“管理 → 标签”（`manage-tags.php`）左侧以标签云列出全部标签，点击标签选中（可以多选），再在“选中项”菜单中操作；右侧是新增 / 编辑表单：

| 界面名称 | 字段 | 说明 |
|---|---|---|
| 标签名称 * | `name` | “这是标签在站点中显示的名称.可以使用中文,如 "地球".” |
| 标签缩略名 | `slug` | 留空时使用标签名称 |

| 操作 | 结果 |
|---|---|
| 删除 | 删除标签及其与文章的关联 |
| 刷新 | 重新计算文章数 |
| 合并到（右侧文本框填写目标标签名） | 所选标签并入目标标签；目标标签不存在时会新建 |

写文章时输入的新标签会自动创建；在标签输入框中，已有标签会作为提示出现。

## 文章数不对怎么办 {#counts}

这是常被问到的问题。分类和标签旁边的“文章数”保存在 `metas` 表的 `count` 字段，每次发布、改状态、删除文章时增减，不是每次实时统计的。下面这些情况会让它看起来“不对”：

| 现象 | 原因 | 处理 |
|---|---|---|
| 后台数字比前台列表多 | **定时发布**的文章（发布日期在将来）已经计入，但到时间之前前台不显示 | 正常现象，到时间后自然一致 |
| 前台列表中有“此内容被密码保护”的条目 | 密码保护的文章计入，也会出现在列表中 | 正常现象 |
| 隐藏、私密、待审核的文章、草稿、修订版本、独立页面没有计入 | 计数只统计**状态为公开**的文章 | 正常现象 |
| 合并标签或分类后数字偏大 | 合并时直接统计所有关联记录，连修订版本、隐藏、待审核的文章也算进去，所以合并后的计数可能大于实际公开的文章数 | 合并后对目标执行一次“刷新” |
| 导入数据、恢复备份或直接修改数据库后，计数不准 | 这些操作不会重新计数 | 全选后“刷新” |
| 有计数为 0 的空标签 | 删除文章后，不再关联任何文章的标签会留下来 | 在标签页手动删除 |

**刷新**：在分类或标签列表中勾选要刷新的项目（可以用表头的复选框全选），在“选中项”菜单中点击“刷新”，确认“刷新分类可能需要等待较长时间……”后执行。刷新后的数字等于关联的、状态为公开的文章数（含定时发布和密码保护的文章）。

:::note 刷新标签不会删除空标签
按照代码的设计，刷新标签时应当顺带删除计数为 0、且不再关联任何内容的标签。但 1.3.0 中这段代码查询的类型名写成了 `tags`（应为 `tag`），实际什么都不会删，刷新后计数为 0 的标签仍然存在。空标签需要在标签页手动选中删除。
:::

导入、迁移之后的批量处理也可参考[从其他博客迁移](../operations/migration.md#counts)。
