# 个人设置

每个能登录后台的用户都有“控制台 → 个人设置”（`admin/profile.php`），也可以点击右上角自己的名字进入。这里修改的只是**你自己**的资料和偏好，不影响其他用户。

页面左侧显示你的头像、昵称、“目前有 N 篇日志, 并有 N 条关于你的评论在 N 个分类中”和最后登录时间；右侧从上到下是下面几个区块。

## 头像 {#avatar}

Typecho 不保存头像图片。后台和前台的头像都来自 [Gravatar](https://gravatar.com/)，按你的**邮件地址**查找：

- 想换头像，到 gravatar.com 用同一个邮箱注册并上传头像；点击个人设置页的头像（提示“在 Gravatar 上修改头像”）也会打开 Gravatar；
- 修改了邮件地址，头像也会随之改变；邮箱在 Gravatar 上没有头像时，显示默认的灰色人像；
- 头像地址是 Gravatar 地址加邮箱（去掉首尾空格、转为小写后）的 MD5，站点使用 HTTPS 时用 `https://secure.gravatar.com`，否则用 `http://www.gravatar.com`；
- 国内访问 Gravatar 较慢时，可以用 `__TYPECHO_GRAVATAR_PREFIX__` 常量换成镜像地址，见[配置文件](../operations/config-file.md)。

## 个人资料

| 界面名称 | 字段 | 说明 |
|---|---|---|
| 昵称 | `screenName` | 前台显示的名字，不能与其他用户的昵称重复 |
| 个人主页地址 | `url` | 需以 `http://` 或 `https://` 开头；1.3 起支持中文等国际化域名 |
| 邮件地址 * | `mail` | 必填，不能与其他用户重复；也可以用来登录，并决定头像 |

点击“更新我的档案”保存，提示“您的档案已经更新”。用户名不能在这里修改。

:::caution 不要清空昵称
界面说明“如果你将此项留空, 将默认使用用户名”，但 1.3.0 中把**已有的**昵称清空后保存，昵称会变成空值，后台和前台都不再显示名字，详见[用户、角色与注册](./users.md)。需要时重新填写昵称即可。
:::

## 撰写设置 {#writing}

**贡献者及以上角色**才有这个区块（关注者不能写文章，所以看不到）。这些设置按用户分别保存在 `options` 表中（`user` 列为你的用户 ID），没有设置过的用户使用安装时的默认值。

| 界面名称 | 选项名 | 默认 | 说明 |
|---|---|---|---|
| 使用 Markdown 语法编辑和解析内容 | `markdown` | 打开 | 打开时编辑器带 Markdown 工具栏和预览，新文章以 Markdown 保存。“此功能开启不会影响以前没有使用 Markdown 语法编辑的内容” |
| 在 XMLRPC 接口中使用 Markdown 语法 | `xmlrpcMarkdown` | 关闭 | 用离线客户端发文时，打开后内容按 Markdown 保存，读取时也返回 Markdown 原文，而不是转换后的 HTML。需要同时打开上一项 `markdown`，否则内容不会按 Markdown 保存。只在客户端本身支持 Markdown 写作时打开，见[订阅源与离线客户端](./feeds-xmlrpc.md#markdown) |
| 自动保存 | `autoSave` | 关闭 | 打开后，编辑器在停止输入 3 秒后自动保存草稿或修订版本，见[撰写文章](./posts.md#drafts) |
| 默认允许 | `defaultAllowComment`、`defaultAllowPing`、`defaultAllowFeed` | 全部勾选 | 三个复选框“可以被评论”“可以被引用”“出现在聚合中”，决定新文章的“允许评论”“允许被引用”“允许在聚合中出现”默认是否勾选；通过 XML-RPC 发布时，客户端没有指定评论、引用设置才使用这里的值，“出现在聚合中”总是使用这里的值 |

点击“保存设置”生效。这些设置按用户生效：例如某用户打开 `markdown` 和 `xmlrpcMarkdown` 后，用这个账号通过 `metaWeblog.newPost` 发布的文章，正文带有 `<!--markdown-->` 标记，其他用户不受影响；客户端没有指定评论、引用设置时，“默认允许”中没有勾选的项在通过 XML-RPC 发布的文章中也会关闭（例如取消“可以被引用”、客户端也没有传 `mt_allow_pings` 时，`allowPing` 为 0）。

## 修改密码 {#change-password}

“密码修改”区块填写“用户密码”和“用户密码确认”（至少 6 位，两次一致），点击“更新密码”，提示“密码已经成功修改”。欢迎页上的“强烈建议更改你的默认密码”就链接到这里。

忘记密码时无法在这里找回，见[用户、角色与注册](./users.md)。

## 插件个人配置 {#plugins}

有的插件除了管理员在“插件”页面中的全站设置外，还提供**每个用户自己的设置**（插件实现了 `personalConfig()`）。启用这类插件后，个人设置页底部会多出以插件名为标题的区块，填写后点击该区块的“保存设置”，值只对你自己生效。

- 区块只对达到插件所要求角色的用户显示。插件没有特别说明时，所有能登录的用户（关注者及以上）都能看到；插件要求贡献者时，关注者的个人设置页中就没有这个区块。
- 插件停用后，区块消失。
- 每个字段的含义请看插件自己的说明。
