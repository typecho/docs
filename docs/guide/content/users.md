# 用户、角色与注册

Typecho 用“用户组”（角色）控制每个账号能做什么。用户在“管理 → 用户”（`admin/manage-users.php`）中管理，**只有管理员**能进入。

:::info 测试情况
本页内容已在 Typecho 1.3.0 + Apache + PHP-FPM（PHP 8.5）+ SQLite 上实测：在后台新建了管理员、编辑、贡献者、关注者账号各一个，分别登录后逐页访问后台、发布和编辑文章、管理评论；打开注册后以访客身份注册了一个账号；用邮箱登录；删除用户。权限表与 `var/Widget/Menu.php`、各 Widget 中的 `pass()` 检查逐条对照过。
:::

## 五个角色

| 角色 | 用户组值 | 一句话 |
|---|---|---|
| 管理员 | `administrator` | 拥有全部权限，包括设置、插件、外观、用户和备份 |
| 编辑 | `editor` | 管理全站内容：所有文章、页面、分类、标签、文件和评论 |
| 贡献者 | `contributor` | 可以写文章，但要经过审核才能发布；只能管理自己的文章和自己文章下的评论 |
| 关注者 | `subscriber` | 只能登录后台修改自己的资料；开放注册时新用户默认是这个角色 |
| 访问者 | `visitor` | 未登录的访客。不能在后台分配给账号，见[下文](#visitor) |

角色是逐级包含的：高一级的角色拥有低一级角色的全部权限。

## 权限分配表 {#permission-table}

后台“编辑用户”页面中用户组下方的“具体的权限分配表请参考这里”指向本节。✓ 表示可以，✗ 表示不可以。

| 操作 | 管理员 | 编辑 | 贡献者 | 关注者 | 访问者 |
|---|---|---|---|---|---|
| 浏览前台、发表评论（评论设置允许时） | ✓ | ✓ | ✓ | ✓ | ✓ |
| 登录后台，查看控制台 | ✓ | ✓ | ✓ | ✓ | ✗ |
| 修改自己的资料和密码（个人设置） | ✓ | ✓ | ✓ | ✓ | ✗ |
| 个人设置中的“撰写设置” | ✓ | ✓ | ✓ | ✗ | ✗ |
| 撰写文章、保存草稿 | ✓ | ✓ | ✓ | ✗ | ✗ |
| 直接发布文章，设置“公开度”（隐藏、私密、密码保护等） | ✓ | ✓ | ✗ 一律进入待审核 | ✗ | ✗ |
| 编辑、删除自己的文章 | ✓ | ✓ | ✓ 再次发布后重新进入待审核 | ✗ | ✗ |
| 编辑、删除他人的文章，审核投稿 | ✓ | ✓ | ✗ | ✗ | ✗ |
| 写文章时选择分类、输入新标签 | ✓ | ✓ | ✓ | ✗ | ✗ |
| 管理分类、标签 | ✓ | ✓ | ✗ | ✗ | ✗ |
| 创建、编辑、删除独立页面 | ✓ | ✓ | ✗ | ✗ | ✗ |
| 上传附件，编辑、替换、删除自己的附件 | ✓ | ✓ | ✓ | ✗ | ✗ |
| 管理所有文件（“管理 → 文件”），清理未归档文件 | ✓ | ✓ | ✗ | ✗ | ✗ |
| 管理自己文章下的评论（审核、回复、编辑、删除） | ✓ | ✓ | ✓ | ✗ | ✗ |
| 管理全站评论 | ✓ | ✓ | ✗ | ✗ | ✗ |
| 不输入密码查看他人的密码保护文章 | ✓ | ✓ | ✗ | ✗ | ✗ |
| 查看他人的私密文章 | ✗ | ✗ | ✗ | ✗ | ✗ |
| 用 XML-RPC 客户端发布和管理文章 | ✓ | ✓ | ✓ 只能管理自己的文章 | ✗ | ✗ |
| 用 XML-RPC 管理页面、分类、作者列表 | ✓ | ✓ | ✗ | ✗ | ✗ |
| 管理用户 | ✓ | ✗ | ✗ | ✗ | ✗ |
| 系统设置（基本、评论、阅读、永久链接） | ✓ | ✗ | ✗ | ✗ | ✗ |
| 插件、外观、编辑主题文件、备份、升级 | ✓ | ✗ | ✗ | ✗ | ✗ |

补充说明：

- 私密文章**只有作者本人**能看到，与角色无关，管理员也看不到别人的私密文章，见[可见性与密码保护](./visibility.md)。
- 插件的个人设置（个人设置页底部）由插件自己声明最低角色，默认是关注者，见[个人设置](./profile.md#plugins)。
- 插件添加的后台页面也由插件指定最低角色，默认是管理员。
- 各页面的入口和菜单显示情况见[后台概览](./admin-overview.md)。

## 新增和编辑用户

在“管理 → 用户”中点击“新增”（`user.php`）：

| 界面名称 | 字段 | 说明 |
|---|---|---|
| 用户名 * | `name` | 登录用的名称，不能与已有用户重复，新建后不能修改 |
| 邮件地址 * | `mail` | 主要联系方式，不能重复；也可以用来登录；头像按这个邮箱从 Gravatar 获取 |
| 用户昵称 | `screenName` | 前台显示的名字，留空则使用用户名 |
| 用户密码 * / 用户密码确认 * | `password` / `confirm` | 至少 6 位；编辑已有用户时留空表示不修改 |
| 个人主页地址 | `url` | 需以 `http://` 或 `https://` 开头 |
| 用户组 | `group` | 下拉框：关注者（默认）、贡献者、编辑、管理员 |

:::caution 编辑用户时不要清空“用户昵称”
按界面说明，昵称留空应当使用用户名。但 1.3.0 中在“编辑用户”或“个人设置”中**把已有的昵称清空**再保存，昵称会变成空值（PHP 同时记录一条 `Undefined array key "name"` 警告），后台和前台都不显示名字。实测如此；新增用户时留空没有这个问题。需要恢复时重新填写昵称即可。
:::

### 用户组下拉框只有四项 {#visitor}

用户组下拉框只提供**关注者、贡献者、编辑、管理员**四个选项，**访问者（visitor）不能手动分配**——它代表没有登录的访客，不是给账号用的角色。

如果一个账号因为直接修改数据库等原因处在 `visitor` 组，实测它仍然可以登录，但所有后台页面（包括控制台和个人设置）都返回 403；在“编辑用户”页面中，它的用户组会显示为第一项“关注者”，直接保存就会变成关注者。

## 用户列表与删除

列表显示每个用户的文章数、用户名、昵称、电子邮件和用户组，可以按关键字筛选。勾选后在“选中项”菜单中删除（确认“你确认要删除这些用户吗?”）：

- **第一个用户**（ID 最小的账号，通常是安装时创建的管理员）和**你自己**不会被删除，勾选了也会被跳过；
- 删除用户**不会删除或转移他的文章和评论**。实测删除一个贡献者后，他的文章仍在，后台文章列表的作者栏变成空白。需要保留署名的话，删除前先把文章交给其他人，或者把账号改成关注者而不是删除。

## 开放注册 {#register}

“设置 → 基本”中的“是否允许注册”（`allowRegister`，默认“不允许”）设为“允许”后，登录页底部出现“用户注册”链接，访客可以在 `admin/register.php` 自行注册：

- 注册表单只有**用户名**和 **Email** 两项。用户名 2 到 32 个字符，邮箱最长 64 个字符，都不能与已有用户重复。
- 注册成功后自动登录，进入欢迎页，页面上显示一次随机生成的 7 位密码，例如“用户 newbie 已经成功注册, 密码为 q1wVUkl”。请提醒用户记下密码并尽快在个人设置中修改。
- 新用户的角色固定为**关注者**，没有任何写入权限，需要管理员手动提升。
- Typecho 不发送任何邮件，注册时也不验证邮箱。

## 登录

- 登录框中的“用户名或邮箱”两者都可以填。实测用邮箱登录成功。
- 同一账号同一时间只能在一处保持登录，新的登录会让之前的登录失效。
- 密码错误时，登录请求会故意延迟约 3 秒再返回，但没有锁定账号的机制，见[安全加固](../operations/security.md)。
- 忘记密码时，后台没有“找回密码”功能。管理员可以在“编辑用户”中为其他用户设置新密码；管理员自己的密码丢失时，见[安装](../getting-started/installation.mdx#安装后丢失管理员密码)。
