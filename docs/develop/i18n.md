# 主题与插件国际化

Typecho 的界面文字以简体中文写成，通过 gettext 的 `.mo` 语言包翻译成其他语言（站长的用法见[界面语言](../guide/extend/languages.md)）。主题和插件中的文字也可以用同一套函数输出，以便被翻译。

## 翻译函数

三个全局函数，定义在 `var/Typecho/Common.php`：

| 函数 | 作用 |
|---|---|
| `_t(string $string, ...$args): string` | 返回翻译后的文字；有额外参数时按 `vsprintf()` 填入 `%s`、`%d` |
| `_e(string $string, ...$args)` | 同 `_t()`，直接输出 |
| `_n(string $single, string $plural, int $number): string` | 按数量选择单数或复数形式，并把其中的 `%d` 换成数字 |

```php
<h2><?php _e('最新文章'); ?></h2>
<p><?php echo _t('共有 %d 篇文章', $count); ?></p>
<p><?php _e('%s 发布于 %s', $this->author->screenName, $this->date->format('Y-m-d')); ?></p>
<p><?php echo _n('一条评论', '%d 条评论', $this->commentsNum); ?></p>
```

- 原文就是翻译的“键”，所以原文一旦发布就不要随意修改，改了之后已有的翻译会对不上。
- 原文中不要直接拼接变量，用 `%s` / `%d` 占位，让翻译者能调整语序。
- `_n()` 在没有语言包时，数量大于 1 用复数形式，否则用单数形式。

站长切换语言后，Typecho 只加载核心语言包（`usr/langs/语言代码.mo`）。主题和插件中的文字如果恰好与核心文字相同（例如“最新文章”“评论”），会用核心语言包的翻译；主题和插件**独有**的文字需要自带翻译文件。

## 加载自己的语言文件

### Helper::lang() 与 I18n::addLang() 的限制

Typecho 提供了 `\Utils\Helper::lang($domain)` 和 `\Typecho\I18n::addLang($file)` 用来追加语言文件，但在 1.3.0 中它们都不适合主题和插件使用：

- `Helper::lang($domain)` 在 `var/Utils/` 目录（`Helper.php` 所在的目录）下查找 `$domain/lang/语言代码.mo`，而不是在插件或主题目录中查找；
- `I18n::addLang()` 追加的文件对 `_t()` / `_e()` **不生效**。查找单数文字时，只要第一个语言文件（核心语言包）中没有这条文字，就直接返回原文，不会继续查找后面追加的文件；只有 `_n()` 会依次查找所有文件。另外，在核心语言包尚未载入时调用 `addLang()` 会出错。

### 推荐写法：自带翻译函数

在主题的 `functions.php`（或插件中）用 `\Typecho\I18n\GetText` 读取自己的 `.mo` 文件，并封装成翻译函数。文件按站点当前的语言选择：

```php title="usr/themes/starter/functions.php"
function starter_t(string $string, ...$args): string
{
    static $gettext = false;

    if (false === $gettext) {
        $gettext = null;
        $siteLang = \Typecho\I18n::getLang();
        if ($siteLang) {
            $file = __DIR__ . '/lang/' . basename($siteLang);
            if (is_file($file)) {
                $gettext = new \Typecho\I18n\GetText($file, true);
            }
        }
    }

    $result = $gettext ? $gettext->translate($string, $count) : $string;
    return empty($args) ? $result : vsprintf($result, $args);
}

function starter_e(string $string, ...$args)
{
    echo starter_t($string, ...$args);
}
```

- `\Typecho\I18n::getLang()` 返回站点当前使用的核心语言包路径（如 `…/usr/langs/en_US.mo`），站点语言为简体中文时返回 `null`；取它的文件名，到主题自己的 `lang/` 目录中找同名文件。
- 模板中用 `starter_e('文字')`、`starter_t('文字')` 代替 `_e()`、`_t()`；没有对应语言文件时原样输出中文。
- 函数名请加上主题或插件的前缀，避免与其他主题、插件冲突。插件中可以写成插件类的静态方法。

目录结构：

```text
usr/themes/starter/
├── functions.php
└── lang/
    ├── messages.pot   翻译模板
    ├── en_US.po       翻译源文件
    └── en_US.mo       编译后的文件，与核心语言包同名
```

## 生成 .pot

翻译模板（`.pot`）列出所有需要翻译的原文。用 GNU gettext 的 `xgettext` 从 PHP 文件中提取，把自己的翻译函数加为关键字：

```bash
xgettext --language=PHP --from-code=UTF-8 \
  --keyword=_t --keyword=_e --keyword=_n:1,2 \
  --keyword=starter_t --keyword=starter_e \
  -o lang/messages.pot $(find . -name '*.php')
```

在主题或插件的目录中执行。之后：

1. 翻译者用 [Poedit](https://poedit.net/) 等工具从 `messages.pot` 新建或更新 `en_US.po`，填写译文；
2. 编译为 `.mo`：

   ```bash
   msgfmt -o lang/en_US.mo lang/en_US.po
   ```

3. 把 `.mo` 与主题或插件一起发布。文件名必须与核心语言包相同（`en_US.mo`、`ja_JP.mo` 等），上面的翻译函数才能找到它。

Typecho 自己的 `messages.pot` 由 Typecho 源码中的 `tools/build_pot.php` 生成：它扫描整个 Typecho 目录中 `_t`、`_e`、`_n` 的字符串参数，不能指定其他目录，也不认识自定义的函数名，所以主题和插件请用 `xgettext`。

## 注意事项

- `_t('')`（空字符串）在加载了语言包时会因为返回值类型错误而报错，不要翻译空字符串。
- 翻译函数只处理字面文字。数据库中的内容（文章、分类名、站点名称）不经过翻译。
- 日期中的月份、星期名称由 PHP `date()` 输出，不会随语言变化。
