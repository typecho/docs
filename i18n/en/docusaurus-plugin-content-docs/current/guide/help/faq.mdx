# FAQ

These are the questions site owners ask most often. Each entry only gives the cause and the direction; follow the link for the detailed steps. If you do not find an answer, see [Getting help](./getting-help.md).

## The home page opens, but every post link returns 404 {#404}

Permalinks (URL rewriting) are enabled, but the web server does not pass these URLs to `index.php`. Depending on the server, check nginx's `try_files`, Apache's `mod_rewrite` and `.htaccess`, or Caddy's `php_fastcgi`; a failed rewrite check under **Permalinks** (永久链接) in the admin panel is covered on the same page. See [Web server configuration: all posts return 404](../operations/web-server.md#404-everywhere).

If you only get a 404 **when logging in**, the nginx PHP configuration most likely does not support URLs like `/index.php/action/login`; see the next two entries.

## The page shows "No input file specified." {#no-input-file}

The script path that PHP receives does not exist. Usually PHP has `cgi.fix_pathinfo=0` set while nginx lacks `fastcgi_split_path_info` (in which case logging in also returns 403 `Access denied.`), or `SCRIPT_FILENAME` is wrong, nginx and PHP-FPM see different paths in a container, or `open_basedir` restricts access. See [Web server configuration: No input file specified](../operations/web-server.md#no-input-file).

## Logging in returns 404, 500 or 403 {#login-fails}

The login form submits to `/index.php/action/login`; if this URL is not passed to `index.php` correctly, login fails. The common cases are:

- **404**: the nginx PHP `location` is written as `location ~ \.php$`, and `location /` has no `try_files ... /index.php$is_args$args` fallback;
- **500**: the old `if (!-e $request_filename) rewrite` style is used, and the rewrite loops;
- **403 `Access denied.`**: PHP has `cgi.fix_pathinfo=0` set and nginx lacks `fastcgi_split_path_info`, or you are using Caddy.

Logging in works with the nginx and Caddy configurations given in the documentation (Caddy with `cgi.fix_pathinfo=0` needs two extra rewrite lines). None of the incorrect configurations above returns 405. See [Web server configuration: login fails](../operations/web-server.md#login-fails).

## 500 / blank page after upgrading or enabling a plugin {#500}

First turn on debug mode or look at the PHP error log to find the actual error, then narrow it down with the "disable all plugins, switch back to the default theme, restore one by one" procedure; if you cannot get into the admin panel, you can disable plugins directly in the database. See [Debugging and troubleshooting](../operations/debugging.md#isolate).

If **Complete upgrade** (完成升级) keeps loading when you upgrade to 1.3.0, it may be the known issue caused by a large number of attachments; see [Upgrading](../getting-started/upgrade.md).

## Where are uploaded attachments stored? {#uploads}

By default in `usr/uploads/year/month/` in the site directory; the database only records the relative path. You can use constants such as `__TYPECHO_UPLOAD_ROOT_DIR__` to put the files elsewhere and `__TYPECHO_UPLOAD_URL__` to serve attachments from a CDN; storing them in object storage requires a plugin. See [Attachment storage location](../operations/uploads-storage.md).

## How do I migrate from WordPress / Emlog? {#migrate}

For WordPress you can use the WordpressToTypecho plugin from the official plugin repository to import posts, pages, categories, tags and comments, but it clears existing content first, it has not been updated since 2021 and has not been adapted to 1.3, so try it on a test site first. There is no official import tool for Emlog. See [Migrating from other blogs](../operations/migration.md).

## How do I back up my site? {#backup}

A full backup consists of three parts: the database (with the database's own export tool), the `usr/` directory, and `config.inc.php`. **Dashboard → Backup** (控制台 → 备份) in the admin panel only exports content, without settings or any files, and cannot replace a full backup. See [Backup and restore](../operations/backup.md).

## Can I change the admin path `/admin/`? {#admin-path}

Yes: change `__TYPECHO_ADMIN_DIR__` in `config.inc.php` and rename the `admin` directory to the same name; you need both steps. See [Custom admin path](../operations/admin-dir.md).

## I forgot the administrator password {#lost-password}

Typecho has no "recover password" feature. You can ask another administrator to reset it in the admin panel, or set the password field in the database to the MD5 of a new password, log in, and then set the password once more. See [Installation: losing the administrator password after installation](../getting-started/installation.mdx#安装后丢失管理员密码).

## The post counts of categories and tags are wrong {#counts}

Post counts are stored in the database and are not recalculated automatically after an import, a restore or a manual database change. In **Manage → Categories** (管理 → 分类) or **Manage → Tags** (管理 → 标签), select all and click **Refresh** (刷新) in the **Selected items** (选中项) menu; after refreshing, only published posts are counted. See [Migrating from other blogs: wrong post counts for categories and tags](../operations/migration.md#counts).
